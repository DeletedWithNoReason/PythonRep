# Рефакторинг «Блокнота Барахольщика»

## 1. Запахи коду (`Code Smells`) у `blocknot.py`

1. **Глобальний змінний стан (`rich = []`)**
   * *Де:* глобальний список `rich` змінюється у `load()` та `add()` і читається у `zvit()`. При повторному запуску `zvit()` записи накопичуються в тому самому списку.
   * *Лікування:* винести стан у `dataclass Inventory` і повертати новий екземпляр під час завантаження.

2. **Дублювання логіки розрахунку вартості**
   * *Де:* у `zvit()` двічі повторюється однаковий розбір станів (`"зламаний"` -> `0.2`, `"уживаний"` -> `0.7`, інакше повна вартість) — окремо для загальної суми `vsoho` і для кожного рядка `s`.
   * *Лікування:* інкапсулювати множники у `Condition` та розрахунок у методі `Item.total_value()`.

3. **Магічні числа, рядки та індекси кортежів**
   * *Де:* коефіцієнти `0.2`, `0.7`, текстові назви станів та звернення до полів через `r[0]..r[5]`.
   * *Лікування:* використати `Enum Condition`, іменовані константи для коефіцієнтів та `dataclass Item` із явними полями.

4. **Незакритий файл у `load(f)`**
   * *Де:* `for l in open(f, encoding="utf-8"):` відкриває файл без контекстного менеджера `with`.
   * *Лікування:* читати файл через `with path.open("r", encoding="utf-8") as fh:`.

5. **Невдале іменування та змішування обов'язків**
   * *Де:* однолітерні/неінформативні змінні (`rich`, `l`, `x`, `r`, `t`, `s`, `vsoho`) і функція `zvit()`, яка одночасно завантажує дані, рахує метрики, сортує та друкує результат.
   * *Лікування:* розділити модель даних (`Item`), колекцію (`Inventory`), серіалізацію в CSV і рендеринг звіту.

## 2. Нова реалізація (`inventory_system.py`)

* `Condition(str, Enum)` — стани `NEW` (`"новий"`), `USED` (`"уживаний"`), `BROKEN` (`"зламаний"`) із коефіцієнтами вартості.
* `Item` (`@dataclass(order=True)`) — поля `category`, `value`, `name`, `quantity`, `condition`, `location`, `added_at` (де `added_at` має `compare=False, repr=False`), метод `total_value()` і форматування `__str__()`.
* `Inventory` — методи `add_item()` (із захистом від дублікатів назв), `remove_item()`, `find_by_category()`, `total_inventory_value()`, `filter_items()`, `sorted_items()`, `export_summary()`, `save_to_csv()` та `load_from_csv()`.
* Збереження старого звіту без змін через `render_legacy_report()` із перевіркою по `golden_master.txt` у `test_golden_master.py`.

## 3. Робота з помічником та Golden Master

* **Що зафіксував Golden Master:** точний текстовий вивід старого скрипту (`Барахла: 7`, сортування за локацією, вивід через `round(..., 2)` і підсумок `Разом: 1563.7`).
* **Що довелося дотиснути і перевірити самому:**
  * У Windows PowerShell перенаправлення `>` створило `golden_master.txt` у UTF-16 LE з BOM, через що читання в UTF-8 спершу дало `UnicodeDecodeError` — перезаписав файл у UTF-8 із `\n`.
  * У форматуванні чисел для сумісності зі старим звітом важливо було залишити вивід `round(num, 2)` через `str(...)` (`160.0`, `150.0`), а не відкидати десяткову частину чи примусово дописувати зайві нулі.
  * Для `order=True` у `Item` порядок полів задано так, щоб спочатку сортувалося за `category`, а потім за `value` (від меншого до більшого), без впливу `added_at`.
